# Задача в YouGile → объекты работ → KML (→ пролёты)

Вход: ссылка на задачу YouGile или её номер (`PRE-2465`, `ID-18612`, uuid).
Выход: папка `YouGile\<PRE-xxxx>\` с дампом задачи и вложениями; KML объектов в `Пролеты\` (транслит, пробелы → `_`); список уточняющих вопросов; при площадных объектах с координатами — миссии Litchi через навык `litchi-flight`.

Файлы навыка:
- `yg_task.ps1` — по ссылке/номеру находит задачу, сохраняет `task.txt` (описание + чат + список вложений), `task.json`, скачивает вложения в `files\` и распаковывает архивы (если стоит 7-Zip).
- `yg_post.ps1` — отправка сообщения в чат задачи (только после явного «да» на конкретный текст).
- `УСТАНОВКА.md` — как получить ключ API и куда положить.
- `ОТЗЫВ.md` — шаблон отзыва по итогам работы.

## 0. Проверка окружения

1. Ключ API: файл `yougile_key.txt` в папке проекта (или `%USERPROFILE%\.claude\yougile_key.txt`). Если нет — остановиться и выдать пользователю только инструкцию из `УСТАНОВКА.md` (создать ключ он должен сам, пароль от YouGile Claude не вводит). Ключ в чат не выводить, в git не коммитить.
2. Работать из папки проекта (там, где `Пролеты\`, KML участков). Все результаты — туда.
3. Если по итогам нужны пролёты — дополнительно всё из навыка `litchi-flight` (браузер с расширением, VPN, вход в хаб).

## 1. Забрать задачу

```powershell
& "<папка скилла>\yg_task.ps1" -Task "<ссылка или PRE-xxxx>"
```
Прочитать `YouGile\<PRE-xxxx>\task.txt` целиком (описание, чат по порядку, список файлов), затем вложения:
- `.pdf` — инструмент Read (страницами, если большой);
- `.xlsx` — распаковать как zip (`unzip` в Git Bash или `Expand-Archive`), читать `xl/sharedStrings.xml` + `xl/worksheets/sheetN.xml`; в чужих таблицах колонки бывают перепутаны (широта/долгота) — проверять по здравому смыслу (для Сибири широта 50–70, долгота 80–110);
- `.doc/.docx` — docx = zip → `word/document.xml`; старый `.doc` читать нечем — попросить пользователя пересохранить, если он нужен;
- архивы `.7z/.rar/.zip` — `yg_task.ps1` распаковывает через `C:\Program Files\7-Zip\7z.exe`; без 7-Zip — попросить установить;
- картинки — Read.
Не пересказывать пользователю всё содержимое — только то, что относится к объектам и координатам.

## 2. Понять, что за объекты (главный шаг)

Составить таблицу объектов: название, тип, где сказано, что известно о положении, источник (сообщение/файл). Типы, которые встречались:

| Тип | Признаки | Что делать |
|---|---|---|
| **A. Площадной объект с координатой/контуром** — карьер, участок, делянка | в чате/xlsx есть координаты (градусы-минуты или десятичные), KML, ссылка на карту; в письме заказчика «карьер X в 6 км СВ п. Y» | → KML контура по `litchi-flight/kml_from_point.md`, → пролёт по `litchi-flight`. Пример: ID-18612 (КрайДЭО, четыре карьера, координаты в `Координаты (2).xlsx` + `Обзорная_схема_участков.pdf`) |
| **B. Линейные объекты — ВЛ по названиям** — тендеры на расчистку трасс | объекты = «ВЛ 110 кВ ПС A – ПС B», пролёты опор №№, га из смет; координат нет | → подстанции A и B найти в OSM (Overpass, `power=substation`, name), трассу — по `power=line` между ними (в OSM подписана только часть 35–110 кВ; 0,4–10 кВ нет). KML: полилиния трассы или, если не найдена, две точки ПС + прямая с пометкой «трасса не подтверждена». Атрибуты: напряжение, га, пролёты. Примеры: PRE-2464/2465/2466 (Россети Юг) |
| **C. Только описание словами** — «участок у деревни N», «лесничество, квартал, выдел» | нет ни координат, ни названий, привязываемых к карте | → список вопросов заказчику; KML не делать «на глаз» |

Правила:
- Координаты из Яндекс-ссылки: `whatshere[point]=lon,lat` — **долгота первая**.
- Длины/площади из документов (длина вала, га расчистки) — сохранять в описание Placemark: это проверка контура (периметр карьера ≈ длина вала).
- Если в задаче несколько объектов — один KML на объект (для пролётов) + один сводный `YouGile\<PRE>\<PRE>_объекты.kml` с папками по объектам.

## 3. Уточняющие вопросы

Сформулировать коротким списком (что именно не хватает по каждому объекту и зачем). Два адресата:
- **пользователю** — всегда, в ответе;
- **в чат задачи YouGile** — только если пользователь скажет. Показать точный текст, дождаться «да», затем `yg_post.ps1 -TaskId <id из task.txt> -Text "…"`. Без «да» ничего не отправлять.

Типовые вопросы: координаты центров/углов в WGS-84; есть ли KML/SHP/DXF у заказчика; какая часть периметра/трассы в работе; откуда брать материал/подъезд; нужен ли облёт.

## 4. KML

Формат как в `litchi-flight/kml_from_point.md`: `lon,lat,0`, кольцо замкнуто, `<name>` можно русским, имя файла — транслит. Для ВЛ — `<LineString>`; для точек ПС — `<Point>`. В `<description>` — источник данных (номер задачи, файл, сообщение) и степень уверенности («по координатам заказчика» / «обведено по спутнику» / «трасса по OSM» / «прямая между ПС, трасса не подтверждена»).

## 5. Пролёты

**Пролёты нужны не всегда. Самостоятельно их не строить.** После того как KML готов и показан, задать один вопрос:
> KML готов. Строить пролёты (миссии в Litchi) по этим объектам? Если да — по каким и на какой высоте (по умолчанию 100 м)?

Строить только после явного «да» и только для площадных объектов (тип A). Если пользователь в исходном запросе уже прямо написал «сделай KML и пролёты» — вопрос не задавать, делать. Дальше полностью по навыку `litchi-flight`, начиная с проверки окружения.

## 6. Отчёт пользователю

Коротко: какие объекты найдены (таблица), что сделано (KML/миссии со ссылками), что не удалось и почему, список вопросов, где лежат файлы.

## 7. Обратная связь (обязательно, в конце каждой работы по навыку)

После отчёта попросить пользователя одной фразой:
> Навык тестовый. Напишите, пожалуйста, что было не так или чего не хватило, в файл `ОТЗЫВ_<PRE-xxxx>_<дата>.md` (шаблон — `ОТЗЫВ.md` в папке навыка, можно просто списком) и отправьте его на **invin@bk.ru** — по этим отзывам навык дорабатывается.

Если пользователь хочет — создать файл отзыва из шаблона прямо в папке `YouGile\<PRE-xxxx>\` и заполнить его его словами. Отправить письмо Claude сам не может — только подготовить файл.

## Подводные камни
- В PowerShell 5.1 имена переменных без учёта регистра: `$Task` (параметр) и `$task` — одна переменная. Скрипты навыка это учитывают; при правках не заводить одноимённые.
- `.ps1` с кириллицей сохранять с BOM (UTF-8 with signature), иначе PowerShell 5.1 читает их как ANSI и ломается на строках.
- `task-list` отдаёт по 1000 задач, новые — в начале; поиск по `PRE-xxxx` листает страницы (у компании >2000 задач — секунды).
- Вложения-картинки в чате имеют суффикс `?previews[]=…` — оригинал по тому же пути без суффикса может отдавать 404; это не критично.
- Ключ API — бессрочный, на пользователя; у каждого, кто пользуется навыком, должен быть свой (создаётся один раз, см. `УСТАНОВКА.md`).
