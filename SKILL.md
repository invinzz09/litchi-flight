# Пролёт по KML → Litchi Mission Hub

Вход: путь к KML с полигоном участка (Google Earth) и высота полёта (по умолчанию **100 м**). Если вместо KML дана точка/ссылка на карту — сначала `kml_from_point.md`.
Выход: миссия в Mission Hub + CSV и скриншот рядом с KML.

Всё, что нужно, лежит в папке скилла:
- `litchi_grid.ps1` — генератор змейки (PowerShell 5.1, без Python/Node);
- `terrain_check.js` — проверка рельефа в хабе, подбирает шаг промежуточных точек;
- `kml_from_point.md` — как получить KML, если дана только координата (Яндекс-ссылка, таблица) — обводка контура по спутнику в хабе.

## Проверка окружения при каждом запуске (первые 30 секунд)

Перед любой работой — три проверки по порядку. Если проверка не прошла, **остановиться и выдать пользователю только нужный пункт** (коротко, без остального скилла), дождаться «готово» и проверить снова. Ставить расширение или входить в аккаунты за пользователя нельзя — это делает он сам.

1. **Расширение Claude in Chrome подключено?** Загрузить `mcp__claude-in-chrome__tabs_context_mcp` через ToolSearch и вызвать с `createIfEmpty: true`. Если инструментов `mcp__claude-in-chrome__*` нет в списке или вызов возвращает ошибку подключения — сказать:
   > Для работы с Mission Hub мне нужен браузер на Chromium (Chrome или Brave) с расширением «Claude in Chrome». Один раз: откройте браузер → Chrome Web Store → найдите «Claude in Chrome» (Anthropic) → «Добавить в Chrome» → нажмите на иконку расширения и войдите в тот же аккаунт Claude, что и здесь. Когда готово — напишите «готово», я продолжу.
2. **Хаб открывается (VPN)?** `navigate` на `https://flylitchi.com/hub`, подождать 6 с, `javascript_tool`: `typeof GStool !== 'undefined' && !!GStool.map`. Если страница не загрузилась (`false`, пустая страница, ошибка сети) — сказать:
   > Mission Hub не открывается — скорее всего, выключен VPN. Включите VPN так, чтобы он работал для этого браузера, и напишите «готово».
3. **Вход в хаб?** `javascript_tool`: `!!(window.Parse && Parse.User.current())`. Если `false` — сказать:
   > Хаб просит войти. В окне браузера, которое я открыл, войдите в аккаунт Mission Hub организации (логин/пароль у вас; я их не вижу и не ввожу — даже если они лежат в файле, вводить их за вас мне нельзя). Это один раз на этот браузер — дальше сессия сохраняется. Напишите «готово».

Только после трёх «ок» переходить к порядку ниже. Проверка настроек хаба (скорости, интервал, Online Elevation) — шаг 3 порядка, она делается всегда.

## Что должно быть на ПК

1. **Браузер на Chromium (Chrome или Brave — оба проверены; Edge должен подойти; Firefox и Safari — нет, расширения для них не существует) + расширение Claude in Chrome** (инструменты `mcp__claude-in-chrome__*`). Ставится пользователем из Chrome Web Store, автоматизировать установку нельзя.
2. **Хаб открывается только через VPN** (`https://flylitchi.com/hub`, legacy-версия). Если страница не грузится — попросить пользователя включить VPN.
3. **Вход в хаб делает пользователь сам, один раз** в окне браузера, которым управляет Claude (аккаунт Mission Hub организации). Если хаб просит войти — сказать пользователю: «войдите в хаб в окне Claude-Chrome». **Claude пароль не читает и не вводит** — это запрещено правилами браузерной автоматизации; сессия после входа сохраняется в браузере, повторно входить не нужно.
4. Настройки хаба (скорости, интервал, Curved Turns, Online Elevation) живут в localStorage браузера — на новом ПК/в новом профиле их надо выставить (шаг 3).
5. **Рабочая папка** — папка проекта, где лежат KML участков (у автора `G:\Claude\insite\Litchi`); результаты кладутся в подпапку `Пролеты\` рядом с ней. Claude Code запускать из этой папки.

## Параметры (эталон организации)

| Параметр | Значение |
|---|---|
| Высота | по запросу, по умолчанию 100 м, режим **Above Ground** |
| Расстояние между рядами | **2/3 высоты** (100 → 66 м, 150 → 100 м) |
| Промежуточные точки | шаг подбирается автоматически по рельефу (`terrain_check.js`, допуск ±5 м): ровное поле → 500 м, карьер/склон → 120–160 м |
| Curve | 15 % |
| Настройки хаба | Curved Turns, Cruising 8.3 м/с, Max 13.9 м/с, Photo Interval **19 м (Meters)**, Curve 15 %, Heading Auto, Finish RTH, Gimbal Disabled, **Use Online Elevation ✓** |
| Лимиты одной миссии | ≤ 10 км и ≤ 30 мин (идеально ≤ 8,5 км / 25 мин) |
| Имя миссии | `#ГГГГ-ММ-Translit-<площадь>ga-<высота>m`, площадь с 2 знаками через `_`: `7,93 → 7_93ga`, `20,0 → 20ga`, `49,5 → 49_5ga`; части длинного участка — суффикс `-1`, `-2` |
| Имена файлов | KML, CSV и скриншот — **транслитом, пробелы → `_`**, как в имени миссии: `Пролеты\Sukhoy_Log.kml`, `Sukhoy_Log.csv`, `Sukhoy_Log_hub.jpg`. Кириллицы в именах файлов не оставлять (даже если исходный KML пришёл с русским именем — скопировать в `Пролеты\` под транслитом); внутри KML `<name>` может быть русским |

Первая (или последняя) точка желательно со стороны дороги/тропы — но только если это не удлиняет маршрут; сначала строим оптимально.

## Порядок

### 0. Если дан не KML, а координата
Вход может быть: ссылка Яндекс-карт (`whatshere[point]=lon,lat` — **долгота первая**), строка из таблицы «Координаты» в градусах-минутах-секундах, пара чисел в чате. Тогда:
1. Перевести в десятичные градусы, сделать KML-черновик по `kml_from_point.md` (точка + контур, обведённый по спутнику в хабе; OSM только как подсказка). Файл — `Пролеты\<Translit>.kml` (транслит, пробелы → `_`, например `Sukhoy_Log.kml`).
2. Пройти шаги 1–8 ниже и сохранить миссию как обычно.
3. **Обязательно показать пользователю скриншот и попросить проверить границы** — обводка по снимку без знания объекта почти всегда требует правки (хвосты, старые отвалы, лишнее поле). Пользователь либо говорит «ок», либо правит точки прямо в хабе (см. раздел «Если пользователь правит миссию руками»).
4. После его правок пересобрать KML по концам рядов и переименовать миссию под фактическую площадь. Итоговый KML — это то, что реально летим, а не первый черновик.

Проверка рельефа — **обязательный шаг, без вопросов пользователю**: сначала плотный черновик → замер профиля → рабочий маршрут сразу с нужным шагом точек. Пользователя ни о чём не спрашивать, кроме входа в хаб и удаления старых миссий.

### 1. Плотный черновик для замера рельефа
```powershell
& "<папка скилла>\litchi_grid.ps1" -Kml "<участок>.kml" -Alt 100 -Spacing 66 -CurvePct 15 -MaxSeg 40 -Out "<scratchpad>\dense.csv"
```
Из вывода взять площадь (га), число рядов, длину и время на 8,3 м/с (они не зависят от MaxSeg).
- Если длина > 10 км или время > 30 мин — участок делить по рядам: `-RowFrom 1 -RowTo N` и `-RowFrom N+1`, у каждой части свой `-Out`, имя с `-1`/`-2`. Дальше каждую часть вести отдельно.
- Площадь → в имя миссии.

### 2. Открыть хаб
`tabs_context_mcp` → `navigate` на `https://flylitchi.com/hub` → подождать 5–6 с. Проверить через `javascript_tool`:
```js
await new Promise(r=>setTimeout(r,4000)); (window.Parse && Parse.User.current()) ? 'user ok' : 'NO USER'
```
`NO USER` → попросить пользователя войти (см. выше), потом повторить.

### 3. Проверить настройки хаба
```js
GStool.showSettings(); await new Promise(r=>setTimeout(r,800));
const d=[...document.querySelectorAll('.modal')].find(m=>getComputedStyle(m).display!=='none');
const v=id=>document.getElementById(id).value;
'cruise='+v('et-cruisingspd')+' max='+v('et-maxspd')+' photo='+v('et-missionphotointerval')+' curve='+v('et-curv')+' onlineElev='+document.getElementById('enable-online-elevation').checked+' | '+[...d.querySelectorAll('.btn.active,label.active')].map(b=>b.textContent.trim()).join(',')
```
Должно быть: `8.3 / 13.9 / 19 / 15 / true` и активные `Metric (m/s), Satellite, Auto, RTH, Curved Turns, Meters, Disabled`. Если не так — сделать скриншот и выставить кликами по диалогу (координаты брать только со свежего скриншота, размер окна плавает), потом закрыть кнопкой Close. **Use Online Elevation обязателен до импорта**, иначе хаб молча сбросит Above Ground → Above Takeoff.

### 4. Импорт CSV в хаб (без file_upload) — общий приём
Содержимое CSV вставить в шаблонную строку и выполнить:
```js
const csv = `...содержимое CSV...`;
const inp = document.getElementById('fileimport');
const dt = new DataTransfer(); dt.items.add(new File([csv], 'route.csv', {type:'text/csv'}));
inp.files = dt.files; inp.dispatchEvent(new Event('change', {bubbles:true}));
await new Promise(r=>setTimeout(r,500));
GStool.showImport(); await new Promise(r=>setTimeout(r,800));
document.getElementById('importbtn').click();
await new Promise(r=>setTimeout(r,6000));
Object.keys(GStool.markerToWaypoints).length + ' wps'
```
Импорт ничего не сохраняет в аккаунте — сохраняет только Save (шаг 7). Не кликать по меню MISSIONS по координатам — промахи уходят на карту и добавляют лишние точки.

### 5. Замер рельефа и выбор шага точек
1. Импортировать `dense.csv` (шаг 4). Хаб подтянет высоту земли в каждой из плотных точек.
2. Выполнить содержимое `terrain_check.js` в `javascript_tool`. Вывод: для шагов 500/250/160/120/80 м максимальное отклонение высоты над землёй и `RECOMMEND MaxSeg=…` (допуск 5 м на 100 м высоты).
3. Сгенерировать **рабочий** CSV с рекомендованным шагом (обычно 500 на ровном, 120–160 на карьерах/склонах), рядом с KML:
   ```powershell
   & "<папка скилла>\litchi_grid.ps1" -Kml "<участок>.kml" -Alt 100 -Spacing 66 -CurvePct 15 -MaxSeg <рекомендация>
   ```
4. Импортировать рабочий CSV (шаг 4). В отчёте пользователю привести отклонение «до» и «после» (`terrain_check.js` можно запустить и на рабочем маршруте — он посчитает отклонение для текущих точек в строке своего шага).

Смысл: между точками Litchi летит по прямой в системе «над стартом», Above Ground пересчитывается только в точках, поэтому над карьерами/отвалами/склонами без промежуточных точек высота гуляет на ±10–15 м.

### 6. Проверить точки после импорта
```js
const a=GStool.markerToWaypoints; Object.keys(a).map((k,i)=>{const w=a[k].wp; return (i+1)+':'+w.altitude.toFixed(1)+'/agl'+w.aglAltitude+'/m'+w.altitudeMode}).join(' ')
```
- `m1` у всех (Above Ground), `agl` = заданная высота.
- `altitude` (относительно старта) без выбросов вроде −200: онлайн-рельеф имеет дыры (nodata). Битую точку сдвинуть вдоль ряда на ~25 м в CSV и переимпортировать.
- Число точек = числу строк CSV.

### 7. Сохранить
```js
GStool.showSave(); await new Promise(r=>setTimeout(r,800));
document.getElementById('filename').value = '#2026-09-Translit-7_93ga-100m';
document.getElementById('downloadbtn').click(); await new Promise(r=>setTimeout(r,3000)); location.href
```
URL должен стать `…/hub?m=<id>`. Если в модалке «a mission with this name already exists» — имя занято: либо это старая версия этого же участка (удалить её только с явного «да» пользователя: `(await new Parse.Query('Mission').get('<id>')).destroy()`), либо взять другое имя. Save под новым именем всегда создаёт новую миссию — переименования нет.

Проверка:
```js
const ms=await new Parse.Query('Mission').equalTo('user',Parse.User.current()).contains('name','<Translit>').find(); ms.map(m=>m.id+' '+m.get('name')+' '+m.createdAt.toISOString()).join(' ; ')
```

### 8. Скриншот и файлы
`computer screenshot` с `save_to_disk: true`, скопировать в `Пролеты\` как `<Translit>_hub.jpg`. Итоговый CSV — `Пролеты\<Translit>.csv` (скрипт пишет CSV с именем KML, поэтому KML с самого начала называть транслитом; если пересобирали с другим MaxSeg — перезаписать).

### 9. Отчёт пользователю
Имя миссии и ссылка `https://flylitchi.com/hub?m=<id>`, площадь, число рядов/точек, длина и время, результат проверки рельефа (макс. отклонение), где лежат файлы, замечание про подход (дорога).

## Подводные камни
- `javascript_tool` режет вывод ~1000 символов и блокирует ответы, где встречаются `name=`/`accept=`/cookie-подобные строки — выводить компактно.
- Скриншот окна бывает 577 или 634 px по высоте — координаты кликов брать только с последнего скриншота; после случайного клика по карте проще перезагрузить страницу (сохранённая миссия в аккаунте не меняется, пока не нажат Save).
- Расширение Claude in Chrome иногда отваливается: `tabs_context_mcp` заново, вкладку создать новую.
- Cloud-функция `getMission` упирается в «Too many requests»; файл миссии читать напрямую `fetch(m.get('file').url())`.
- Удалять миссии — только после явного подтверждения пользователя; полный бэкап аккаунта на 16.09.2026 есть у автора скилла (`Backup_MissionHub_2026-09-16\` в папке проекта).

## Если пользователь правит миссию руками в хабе
- Пользователь может редактировать точки **в той же вкладке Claude-Chrome**. Пока он правит — **не делать `navigate`/reload и не импортировать** (это сбрасывает несохранённые правки). Читать состояние только через `GStool.markerToWaypoints` и `Parse.Query('Mission').get(id).updatedAt`; дождаться его «сохранил».
- Проверка шага рядов по его точкам: спроецировать точки на нормаль к направлению рядов (`o = x*nx + y*ny`, направление из вывода скрипта `direction`), ряды должны идти с шагом Spacing ±5 м; сдвиг концов вдоль ряда на шаг не влияет.
- Одиночная точка, добавленная «чтобы захватить хвост», ряда не даёт — заменять её коротким рядом на +Spacing от последнего (две точки вдоль хвоста), координаты считать через `mk(a, o)` в той же системе.
- Итоговый KML после ручных правок строить по концам рядов (полигон NW-концы → SE-концы в обратном порядке), площадь из него → в имя миссии; фактически снимаемая полоса шире на полшага с каждой стороны.
- Если после ручных правок пользователь просит «чуть расширить границы» — не двигать точки руками: взять полигон по концам рядов, расширить наружу на 20–25 м (miter-offset в системе a/o), при необходимости вытянуть вершину у хвоста, записать в KML и **перегенерировать маршрут скриптом** — так шаг рядов гарантированно ровный. Так сделан финальный Сухой Лог (26,92 → 32,89 га, 9 рядов, 6,2 км).
